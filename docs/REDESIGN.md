# Перенос экранов на новое оформление

Оформление консоли переписано: Tailwind v4 поверх токенов проекта, новая
рамка экрана, панель контекста справа. Этот файл — рабочая инструкция по
переносу оставшихся экранов. Он про то, как переносить, а не про то, почему
так решено: обоснования лежат в комментариях `apps/web/src/styles/tokens.css`.

## Где что лежит

| Файл | Что там |
|---|---|
| `src/styles/app.css` | точка входа; порядок слоёв объявлен явно |
| `src/styles/tokens.css` | палитра, семантика, плотность, мост в Tailwind, печать |
| `src/styles/legacy.css` | правила «Пульта», ещё не переписанные; **вымывается** |
| `src/ui/layout.tsx` | `Page`, `Panel`, `Grid`, `Stack` |
| `src/ui/primitives.tsx` | `Button`, `Field`, `Input`, `Select`, `Tag`, `SeverityTag`, `Stat`, `Num`, `SectionLabel`, `Toolbar` |
| `src/ui/index.tsx` | `DataTable`, `Search`, `Loading`, `Empty`, `Modal`, хуки |
| `src/shell/Rail.tsx` | рельса разделов, сгруппированная |

## Обязательное правило цвета

**Янтарный (`accent`) означает «требует внимания» и больше ничего.** Ни
кнопка «сохранить», ни включённый фильтр, ни выбранная строка им не
красятся — для состояния и действия есть бирюзовый (`primary`). Если
кажется, что нужен янтарный, — экран сообщает о проблеме не тем способом.

Выраженность (`sev-*`) никогда не работает цветом в одиночку: рядом всегда
подпись, а у метки ещё и форма точки. Для этого есть `SeverityTag`.

## Как переносить экран

Было:

```tsx
<>
  <PageHead title={…} sub={…} actions={…} />
  <div className="card">
    <div className="table-tools">…</div>
    <DataTable … />
  </div>
</>
```

Стало:

```tsx
<Page
  title={ut("patients.title")}
  sub={ut("patients.sub")}
  count={total}              {/* число в заголовке, если оно есть */}
  actions={…}                {/* действия справа от заголовка */}
  toolbar={…}                {/* фильтры: прибиты и не уезжают при прокрутке */}
  context={…}                {/* необязательно: панель справа */}
  contextTitle={…}
>
  <Panel flush>              {/* flush — для таблиц во всю ширину панели */}
    <DataTable … />
  </Panel>
</Page>
```

Образец переноса целиком: `src/pages/Patients.tsx` вместе с
`src/components/PatientContext.tsx`.

### Что менять обязательно

1. `PageHead` → `Page`. Число из подписи (`… · 8189`) переезжает в `count`.
2. `div.card` → `Panel`. Заголовок карточки — свойство `title`, пояснение —
   `hint`, кнопки — `actions`.
3. `div.grid.cols-2/3/4` → `<Grid min={320}>`. Колонки задаются минимальной
   шириной, а не числом: на 3/4 экрана «три колонки» превращаются в кашу.
4. Инлайновые `style={{ … }}` — на утилиты. Исключение: значения, которые
   считаются в рантайме (ширина полосы, цвет из данных).
5. `<button className="primary">` → `<Button variant="primary">`;
   `className="ghost"` → `variant="quiet"`; `className="danger"` →
   `variant="danger"`.
6. Классы `.muted`, `.hint`, `.error` → `text-muted`, `text-caption
   text-muted`, `text-danger`.

### Чего не делать

- Не трогать логику: запросы, сортировки, расчёты, права. Перенос —
  про вид.
- Не удалять комментарии-обоснования. Если правило переезжает, комментарий
  переезжает с ним.
- Не заводить новые цвета. Всё нужное уже есть в токенах; если не хватает —
  это повод обсудить, а не добавить хекс в разметку.
- Не добавлять тени панелям. Тень осталась только у всплывающих слоёв.
- Не менять текст интерфейса и не добавлять строки в обход
  `packages/shared/src/uiStrings.ts`.

## Проверка после каждого экрана

```
bun run typecheck        # из apps/web
bun test apps/web/test packages/shared/test
```

Экран должен открываться без ошибок в консоли браузера, работать в обеих
темах (`data-theme` на `<html>`) и в плотном режиме (`data-density`).
Горизонтальной прокрутки у страницы быть не должно ни при какой ширине —
широкое содержимое прокручивается внутри своего контейнера.
